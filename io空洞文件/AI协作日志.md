## 2. 关键决策记录

- **平台**：Linux（鲁班猫 RK3566，ARM64），采用 POSIX `open/lseek/write/stat` 写法；
  Makefile 用 `CC ?= gcc` 支持板载编译与 `aarch64-linux-gnu-gcc` 交叉编译。
- **下载数据来源**：题目为「类似下载功能」且未提供数据源，故 `download` 写入确定性字节模式
  `(offset + i) % 256` 模拟下载数据，便于验证定点写入结果。
- **断点记录方式**：旁路文件 `<file>.progress`，文本保存「已完成偏移」（即下次写入起点）。
- **Ctrl+C 处理**：`signal(SIGINT, ...)` 置 `volatile sig_atomic_t` 标志，循环在块边界保存断点后干净退出。
- **空洞占比公式**：`(1 - st_blocks*512 / st_size) × 100%`。

## 4. 实测记录

> 环境：鲁班猫 RK3566（aarch64）Linux，编译产物 `hole_download`。

**编译**：`gcc -Wall -Wextra -O2 -o hole_download main.c` 一次通过，无警告无错误。

**① 创建空洞文件（create）**

```text
已创建稀疏文件 test.bin, 逻辑大小 131072 字节 (128.00 KB), 断点初始化为 0
```

**② 初始空洞占比 ≈ 100%**：新建 1GB 大文件后 `status`，空洞占比接近 100%（128KB 太小，用大文件验证更直观）。

**③ 下载写入（download）**：分块逐块写入，进度从 0% 增长到 100%。

**④ 断点续传（Ctrl+C）**：用 1GB 大文件，`download` 中途按 Ctrl+C，打印「收到 Ctrl+C, 断点已保存: xxx 字节」；再次 `download` 显示「从断点 xxx 继续」，从断点续传成功。

**⑤ 完成识别**：重复 `download` 输出「文件 test.bin 已下载完成(断点 131072 == 总大小 131072)」。

**⑥ 下载完成后空洞占比 = 0%**

```text
文件: test.bin
逻辑大小:     131072 字节 (128.00 KB)
实际占用块数: 256 块 (实际占用 131072 字节)
空洞占比:     0.00%
```

**⑦ 定点写入（write）**

```text
已在 test.bin 偏移 100 处定点写入 5 字节: "hello"
```

配合 `od -c` 查看偏移 100 附近，可见 `hello` 前后字节未被破坏，证明定点写入不影响其余空间。

## 5. 遇到的问题与解决

1. **目录多一层导致编译报错**：文件整包上传后实际路径为 `~/Desktop/Ke-Cheng-She-Ji/io空洞文件/`，若在 `Ke-Cheng-She-Ji` 下编译会报 `gcc: error: main.c: No such file or directory`。解决：`cd ~/Desktop/Ke-Cheng-She-Ji/io*` 进入正确目录后再编译。
2. **128KB 太小、无法演示 Ctrl+C 断点**：128KB 下载瞬间完成，来不及按 Ctrl+C。解决：改用 1GB 大文件（`create big.bin 1073741824`）放慢进度后再中断。
