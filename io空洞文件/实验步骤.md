# 实验步骤（空洞文件断点续传下载器）

> 所有命令均在板子项目目录 `~/Desktop/Ke-Cheng-She-Ji/io空洞文件` 下执行。

## 〇、编译准备

**首次编译**（在项目目录下）：

```bash
cd ~/Desktop/Ke-Cheng-She-Ji/io空洞文件
ls      # 确认能看到 main.c
gcc -Wall -Wextra -O2 -o hole_download main.c
# 或者用 make：make
```

编译成功后，`ls` 里会出现可执行文件 `hole_download`。

**如果 `hole_download` 不见了**（比如删测试文件时误删）：只要源码 `main.c` 还在，重新编译一次即可：

```bash
ls
gcc -Wall -Wextra -O2 -o hole_download main.c
```

**如果连 `main.c` 都没有了**（源码也被删）：需从 Windows 重新上传源码，再执行上面的编译。

## 一、核心功能演示（断点续传）

> 用大文件（1GB）演示，因为 128KB 太小、下载瞬间完成，来不及按 Ctrl+C。

```bash
# 1. 创建 1GB 稀疏文件（瞬间完成，因为中间全是空洞）
./hole_download create big.bin 1073741824

# 2. 查看初始状态 —— 重点：空洞占比 ≈ 100%
./hole_download status big.bin

# 3. 开始下载，跑几秒后按 Ctrl+C 中断
./hole_download download big.bin 65536
#    预期：逐块打印进度 → 按 Ctrl+C 后出现
#    「收到 Ctrl+C, 断点已保存: xxx 字节」

# 4. 查看中断后的状态 —— 空洞占比下降（部分洞已被填上）
./hole_download status big.bin

# 5. 续传 —— 关键：第一行应显示「从断点 xxx 继续」，而不是从 0
./hole_download download big.bin 65536

# 6. 定点写入
./hole_download write big.bin 100 hello
```

**对照题目要求的检查点**：

| 步骤 | 证明内容 | 题目对应 |
|------|---------|---------|
| 第 2 步 ≈100% | 空洞文件创建成功 | 用文件 I/O 制作空洞文件 |
| 第 3 步中断 + 第 5 步续传 | 断点续传生效 | 记录「已完成偏移」，Ctrl+C 后从断点继续 |
| status 三指标 | 逻辑大小 / 占用块数 / 空洞占比 | status 部分明确要求 |
| 第 6 步 write | lseek+write 定点写入 | 定点写入不破坏其余空间 |

## 二、加分项

### A. 空洞不占磁盘空间（「空洞」的核心价值）

**新建文件后、下载前**立即执行（此时为全洞状态）：

```bash
./hole_download create hole.bin 1073741824
ls -l  hole.bin     # 逻辑大小：1073741824（1GB）
du -h  hole.bin     # 实际磁盘占用：几乎为 0（如 4.0K）
```

结论：逻辑 1GB，物理几乎 0 —— 这就是空洞文件的本质。

### B. 空洞区域读出来是全 0

```bash
od -c -j 100000 -N 16 hole.bin
# 预期：全是 \0 \0 \0 ...（尚未下载到的区域）
```

### C. 验证定点写入只改目标位置、不破坏别处

```bash
./hole_download write big.bin 100 hello
od -c -j 90 -N 24 big.bin
# 预期：偏移 100 处能看到 h e l l o，
#       其前后字节仍是原来的下载数据模式（未被破坏）
```

### D. 看懂断点文件

```bash
cat big.bin.progress
# 内容是一个数字 = 「已完成偏移」，下次 download 从这里继续
```

## 三、清理

```bash
rm -f big.bin big.bin.progress hole.bin hole.bin.progress
```
